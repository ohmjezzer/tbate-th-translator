# 💾 การบีบอัดไฟล์ผลลัพธ์ (Output Compression)

ระบบจะ **บีบอัดภาพผลลัพธ์อัตโนมัติ** เมื่อบันทึกเสร็จ เพื่อให้ไฟล์เล็กพออัปโหลด/ส่งต่อได้
โดย **ค่าดีฟอลต์ = ไม่เกิน 1 MB ต่อหน้า**

## หลักการทำงาน

```
ภาพผลลัพธ์ (typesetting เสร็จ)
        │
        ▼
[1] ลองเข้ารหัสที่ quality สูงสุด (92)
        │  เล็กกว่าเป้า? ──► ใช้เลย
        ▼
[2] binary search หา quality สูงสุดที่ยังไม่เกินเป้า (ช่วง 40–92)
        │  เจอ? ──► ใช้ค่านั้น (คมที่สุดเท่าที่ไฟล์จะรับได้)
        ▼
[3] ยังเกิน? → ย่อขนาดภาพทีละขั้น (ไม่ต่ำกว่า 60%) แล้วลองใหม่
        │
        ▼
ไฟล์ผลลัพธ์ ≤ ขนาดเป้าหมาย (เท่าที่ทำได้)
```

**ทำไมไม่ลด quality คงที่?** เพราะการลด quality แบบคงที่ (เช่น 80) อาจทำให้ไฟล์เล็กเกินจำเป็น
(ภาพไม่คม) หรือใหญ่เกินเป้า — การ binary search ช่วยให้ได้ **คุณภาพสูงสุดที่ยังอยู่ในงบขนาดไฟล์**

## ตั้งค่า (config.json → `output`)

| ฟิลด์ | ดีฟอลต์ | ความหมาย |
|---|---|---|
| `compress` | `true` | เปิด/ปิดการบีบอัดอัตโนมัติ |
| `target_size_mb` | `1.0` | ขนาดสูงสุดต่อไฟล์ (MB) |
| `format` | `"webp"` | `webp` \| `jpeg` \| `png` \| `keep` |
| `min_quality` | `40` | quality ต่ำสุดที่ยอมรับ |
| `max_quality` | `92` | quality สูงสุด (เริ่มค้นหาจากค่านี้) |
| `allow_downscale` | `true` | ย่อขนาดภาพได้ถ้าลด quality ไม่พอ |
| `max_downscale_ratio` | `0.6` | ย่อได้ไม่ต่ำกว่า 60% ของขนาดเดิม |

### ผ่าน environment variable (.env)
```
SCANLATION_OUTPUT_COMPRESS=true
SCANLATION_OUTPUT_TARGET_MB=1.0
SCANLATION_OUTPUT_FORMAT=webp
SCANLATION_OUTPUT_MIN_QUALITY=40
SCANLATION_OUTPUT_MAX_QUALITY=92
SCANLATION_OUTPUT_ALLOW_DOWNSCALE=true
SCANLATION_OUTPUT_MAX_DOWNSCALE_RATIO=0.6
```

### ผ่าน CLI
```bash
python -m scanlation.cli run --target-mb 0.5 --format jpeg    # หน้านี้/เรื่องนี้ → ≤0.5MB, JPEG
python -m scanlation.cli run --no-compress                    # ปิดบีบอัด (ไฟล์เต็มขนาด)
```

## บนหน้าเว็บ Preview

มุมขวาบนมีตัวเลือก:
- **ขนาดไฟล์**: ≤ 0.5 MB / **≤ 1 MB (ดีฟอลต์)** / ≤ 2 MB / ≤ 5 MB / ไม่บีบอัด
- **ฟอร์แมต**: WebP / JPEG / PNG / คงเดิม

กด **⚡ บันทึก & เรนเดอร์ใหม่** → ระบบบีบอัดให้ทันที และแสดงผลที่แถบสถานะ:
`🟢 ไฟล์ผลลัพธ์: 842KB / เป้า 1MB` (🔴 = ยังเกินเป้า)

> 💡 ตัวเลือกนี้ส่งผลเฉพาะครั้งที่กดเรนเดอร์ (override config) — ไม่แก้ไฟล์ config ถาวร

## ฟอร์แมตไหนควรใช้?

| ฟอร์แมต | ข้อดี | ข้อเสีย |
|---|---|---|
| **WebP** (แนะนำ) | เล็กสุดที่คุณภาพเท่ากัน · รองรับทุกระบบอ่านสมัยใหม่ | บางโปรแกรมเก่าอาจไม่เปิด |
| **JPEG** | เข้ากันได้กว้างสุด | เส้นคมชัด (line art) อาจมี noise รอบเส้น |
| **PNG** | lossless คมชัด 100% | ไฟล์ใหญ่มาก มักเกิน 1MB (ระบบจะย่อภาพให้) |
| **keep** | คงนามสกุลเดิม | ไม่เปลี่ยนฟอร์แมต |

> 📌 หมายเหตุ: PNG เป็น lossless — ถ้าตั้งเป้า 1MB ระบบจะ **ย่อขนาดภาพ** ให้แทน
> (เพราะลดขนาดไฟล์แบบไม่สูญเสียทำได้จำกัด) เหมาะกับงานที่ต้องการความคมชัดสูงสุด
